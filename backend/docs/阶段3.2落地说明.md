## 2. 关键设计

### 2.1 引擎按方言分支

```python
_url = settings.database_url
_is_sqlite = _url.startswith("sqlite")

if _is_sqlite:
    engine = create_async_engine(_url, connect_args={"check_same_thread": False, "timeout": 30.0})
else:
    engine = create_async_engine(_url, pool_size=10, max_overflow=20, pool_pre_ping=True, pool_recycle=1800)
```

- SQLite: 保持老 connect_args, 让 aiosqlite 走 WAL 兼容路径.
- PostgreSQL: 走 asyncpg, 启用连接池, pre_ping 防长连接被服务端关闭.

### 2.2 PRAGMA 只挂在 SQLite

```python
if _is_sqlite:
    @event.listens_for(engine.sync_engine, "connect")
    def _enable_sqlite_pragmas(...):
        ...
```

PG 不需要 WAL / busy_timeout, 这些是 SQLite 私有概念.

### 2.3 init_db 双路径

```python
async def init_db() -> None:
    from app import models  # noqa: F401

    if not _is_sqlite:
        from app.core.migrate import run_alembic_upgrade
        await run_alembic_upgrade()
        return

    # SQLite: 保留 create_all + 列补齐
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    ...
```

- PostgreSQL: 走 Alembic upgrade head. 不再 create_all 偷建表, 严格走迁移历史.
- SQLite (回归): 保留原 _COLUMN_BACKFILLS 逻辑, 方便本地快速试.

### 2.4 baseline 迁移

- revision = `20260608_0001_baseline`, down_revision = None
- 覆盖 26 张主要业务表 + 18 个 JSON 列 / 时间戳列补齐
- PostgreSQL 上 `JSON` 列自动用 `JSONB`
- 索引补强: `ix_agent_tasks_pending_pick` / `ix_agent_tasks_lease` / `ix_study_runs_material_status`

baseline 的 `downgrade()` 是空 pass: 业务回滚请走备份 + 新库重建, 不要依赖这个迁移做 down.

## 3. 本地启动

### 3.1 PostgreSQL (推荐)

```bash
cd backend
cp .env.example .env
# .env 默认就是 postgresql+asyncpg://novelforge:novelforge@127.0.0.1:5432/novelforge

# 1) 启动 PG / Redis (项目根目录)
docker compose up -d postgres redis

# 2) 升级到 head
python -m alembic upgrade head

# 3) 启动 API
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动日志里会看到:
```
running alembic upgrade -> head
alembic upgrade done
```

### 3.2 SQLite (回归)

```bash
cd backend
cp .env.example .env
# 把 DATABASE_URL 改回 sqlite+aiosqlite:///./data/novelforge.db

uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动日志里不会调 Alembic, 走 create_all + 轻量补列.

## 5. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| baseline 缺表 / 缺列 | 3.2 阶段先在本地 PG 上跑 `alembic upgrade head`, 然后对业务列表 `select count(*)` 比对 | 改回 SQLite, 删 alembic/versions/baseline |
| `JSONB` 在 SQLite 走 `JSON` | env.py 兼容两种 dialect, baseline 里 `op.get_bind().dialect.name` 分支判断 | 同上 |
| 老 SQLite 业务回归被破坏 | 3.2 显式保留 SQLite 分支, _is_sqlite 走老路径 | 改 DATABASE_URL 切回 SQLite |
| Alembic 与 SQLAlchemy metadata 漂移 | 后续每改一个 model 都同步写迁移; 不再用 create_all 偷建 | 重建 alemic 版本 |
