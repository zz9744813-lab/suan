## 2. 本地启动流程

### 2.1 用 docker compose (推荐)

```bash
# 1. 复制环境变量
cp .env.example .env
cp backend/.env.example backend/.env

# 2. 起 PG / Redis / API / Worker / Frontend
docker compose up -d --build

# 3. 看 5 个服务健康
docker compose ps
docker compose logs -f backend-worker
```

预期：

- `novelforge-postgres` healthy
- `novelforge-redis` healthy
- `novelforge-backend-api` 端口 8000 healthy
- `novelforge-backend-worker` 持续输出 heartbeat 日志
- `novelforge-frontend` 端口 8080 healthy

### 2.2 不想跑 docker 的话

如果要保持现有本地 dev 模式（手动 `uvicorn`）：

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate     # Windows
pip install -e ".[dev]"

# 复制环境变量 (此时保持 SQLite 回归)
cp .env.example .env
# 修改 DATABASE_URL=sqlite+aiosqlite:///./data/novelforge.db

# 启动 API
uvicorn app.main:app --host 127.0.0.1 --port 8000

# 另开终端, 启动占位 Worker
python -m app.workers.runtime_worker
```

> 3.1 阶段你可以不连 Redis/PostgreSQL, 直接保留 SQLite 回归.
> 真正要切到 PG, 至少要等 3.2 (Alembic baseline) 完成后.

## 4. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| 新依赖装不上 | pyproject 显式列出版本区间 | 删除新增行, 重新 `pip install -e .` |
| docker compose 启动失败 | healthcheck + 顺序依赖 | `docker compose down -v && git revert` |
| `config.py` 新字段不兼容老 .env | 新字段都给了默认值, 不读 .env 也能用 | 删字段, 重启服务 |
| 误切到 PostgreSQL 但没数据 | 默认值还是 SQLite, 需手动改 DATABASE_URL 才会切 | 改回 SQLite 即可 |
| 占位 Worker 误以为真的 Worker | 日志明确写 `runtime_worker` + `heartbeat`, 业务无副作用 | 关掉 backend-worker 服务 |
