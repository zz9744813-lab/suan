## 2. 执行模型

```
POST /api/study/materials/from-text
   ↓
StudyRun (status=queued)
   ↓ enqueue
study_deepstudy_dispatch (1 job per run)
   ↓ enqueue (拿 next stage)
study_ds_chapter_profile → 完成
   ↓ enqueue (再入 dispatch)
study_deepstudy_dispatch
   ↓ enqueue
study_ds_entity_extract → 完成
   ↓ enqueue
... 反复, 直至所有 stage 完成
   ↓ finalize
StudyRun (status=succeeded)
```

**关键点**:
- 每个 stage job 持短事务（一次 `_execute_stage`），不再 1167 章一次 commit
- 任何 stage 抛异常 → arq 重试 → 状态机自动推进
- 多 run 可并发（`max_jobs=8` 决定并发上限）

def pick_next_stage(completed_stages: list[str]) -> str | None:
    """顺序 DAG: 拿第一个还没跑完的 stage."""
    done = set(completed_stages or [])
    for key in STAGE_KEYS:
        if key not in done:
            return key
    return None

## 6. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| dispatch 永远循环 (completed_stages 写不进去) | _execute_stage 抛异常时 dispatch 不再自入队; 业务可手动 recover | 关 backend-worker, 改 `WORKER_RUN_IN_PROCESS=true` |
| stage 名称与 DAG 不一致 | `STAGE_KEYS` 写在 `deepstudy_pipeline.py`, 3.5 之前不再扩 | 同步改 `job_graph.DEEPSTUDY_DAG` |
| finalize 在 dispatch 跑后又被 stage 触发二次 | _finalize_run 写 `status=succeeded`, dispatch 会跳过终态 | 无需回滚 |
| 老验收流程被卡 | 默认 `worker_run_in_process=True` 时仍走 in-process, 不动业务 | 改 .env 即可 |
