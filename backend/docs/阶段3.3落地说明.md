## 2. 关键设计

### 2.1 兼容开关

```python
# app/core/config.py
worker_run_in_process: bool = True  # 阶段 3.3 默认 True
```

- ``True``: routers 不入队, 继续 ``get_worker().start()`` 老路径
- ``False``: routers 调 ``enqueue_task``, 由独立 arq Worker 进程消费

切换流程:
  - 阶段 3.3 期间默认 ``True``, 让验收流程不被卡
  - 阶段 3.5 之后切到 ``False``, 并把老 ``httpx`` 兜底删除

### 2.2 handler 设计

``run_agent_task(ctx, task_id, task_type)``:

1. 从 DB 拉 ``AgentTask``, 写 lease (`lease_owner` / `lease_expires_at` / `last_heartbeat_at`)
2. 调 ``WorkerController._run_*`` 业务方法 (chapter_pipeline / reader_review / comment_* / project_bootstrap)
3. 写终态 (succeeded / failed), 清 lease
4. 业务异常 → raise, arq 走 ``on_job_max_retries`` → 写 DLQ

业务代码零改动: ``_run_chapter_pipeline`` / ``_dispatch_event_task`` 都是 WorkerController 已有方法.

### 2.3 域 (domain) 路由

| task_type | domain | 队列名 |
|---|---|---|
| chapter_pipeline / project_bootstrap / rewrite_from_discussion | writing | q:writing |
| reader_review | review | q:review |
| comment_triage / comment_discussion / comment_cleanup | discussion | q:discussion |
| study_* / memory_* | memory | q:memory |
| model_* | model | q:model |

3.4 阶段才会真正在 arq 端启用 ``memory`` 域 handler; 3.3 阶段这些任务会落到 ``ack-only`` 兜底, 不抛.

### 2.4 DLQ

- arq 走完 ``on_job_max_retries`` 后, ``write_dlq`` 把记录写入 ``dlq:{domain}`` 列表, 上限 1000 条.
- ``/api/worker/dlq?domain=writing&limit=50`` 给前端读.

## 3. 本地启动

### 3.1 docker compose (推荐, 真正切到 arq)

```bash
# 1) 后端 .env 切到独立 worker 模式
echo "WORKER_RUN_IN_PROCESS=false" >> backend/.env

# 2) 起 5 个服务
docker compose up -d --build

# 3) 看 arq worker 日志
docker compose logs -f backend-worker
# 期望: "arq worker started worker_id=..."

# 4) 触发写小说启动, 观察 enqueue
curl -X POST http://localhost:8000/api/projects/1/launch -d '{...}' -H 'Content-Type: application/json'

# 5) 看队列深度
curl http://localhost:8000/api/worker/queue-summary
```

### 3.2 不切 arq, 走老 in-process

```bash
# backend/.env 保持 WORKER_RUN_IN_PROCESS=true
docker compose up -d --build
# 此时 backend-api 进程内自动跑 Worker, backend-worker 容器空转
```

### 3.3 Smoke

```bash
cd backend
python -m app.scripts.smoke_redis_enqueue --task-type chapter_pipeline
```

## 5. 风险与回滚

| 风险 | 缓解 | 回滚 |
|------|------|------|
| arq 与 WorkerController 状态机冲突 | handler 不跑 _tick 循环, 只调业务函数 | 关 backend-worker, 改 .env `WORKER_RUN_IN_PROCESS=true` |
| 入队失败导致业务无限等 | enqueue_task 仅 warning, 不抛 | router 已有 try/except |
| DLQ 写满 | 列表长度截到 1000, 不影响业务 | 用 `/api/worker/dlq` + redis-cli `LTRIM` |
| 业务代码兼容 | handler 复用 WorkerController 业务方法, 3.3 阶段不改业务 | 关 backend-worker, 改 .env |
