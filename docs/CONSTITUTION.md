# 玄鉴最高宪法

> 来源：工程方案 v1.0 第 1.2 节 与 第 86 节
> 版本：constitution-1.0
> 适用：所有 Agent、所有规则、所有代码路径

---

## C-001 可证伪原则

**无法失败的预测，不允许进入正式预测账本。**

禁止：

```text
最近可能有些变化。
需要注意人际关系。
未来存在机遇。
可能先坏后好。
```

允许：

```text
预测窗口：2026-09-01 ~ 2026-09-07

事件：
至少发生一次未在前一日计划中的工作任务，
并造成原计划改变 ≥ 30 分钟。

预测概率：0.67

验证：发生 / 未发生 / 部分发生 / 无法判断
```

## C-002 预测先于结果原则

正式预测必须在结果发生前：

- 生成；
- 写入数据库；
- 写入完整时间戳；
- 保存模型版本；
- 保存 Prompt 版本；
- 保存术数规则版本；
- 保存输入快照；
- 计算内容哈希；
- 冻结。

**结果出现以后禁止覆盖原预测。**

## C-003 不允许事后改口

预测发布后如果需要修订，只能：

```text
Prediction v1
↓
Revision v2
```

而不能覆盖 v1。原版本永久存在。

## C-004 全失败样本保留

不能只保存「算准了」的预测。系统必须永久保存：

- 命中；
- 未命中；
- 部分命中；
- 无法验证；
- 用户拒绝验证；
- 数据不足；
- 被对抗审查拦截。

## C-005 概率而不是绝对断言

核心输出必须使用概率，而不是：

```text
今天必有贵人。
```

## C-006 不得假设传统术数具有科学预测效力

紫微、八字、六爻、奇门、梅花、面相、掌纹等作为 **Traditional Metaphysical Signals** 进入系统。其有效性必须由系统自己的长期验证结果决定。

## C-007 现实优先

涉及真实世界决策时：

```text
现实证据 > 可验证历史规律 > 传统术数解释
```

尤其是：医疗、法律、财务、安全、高风险职业决策。系统不得以术数预测代替专业判断。

## 硬性原则（第 86 节）

> **未经验证的预测不是知识。**

> **无法失败的预测不是预测。**

> **发生以后才补出来的解释，不算预测能力。**

> **如果 Null Model 比玄学模型更强，就必须承认玄学模型没有贡献。**

> **所有命中与失败必须同时保留。**

> **LLM 负责解释、假设、归因与综合；确定性计算必须交给程序。**

> **任何「系统变得更准」的结论，都必须由冻结预测和后验现实数据证明。**

> **第一性原理审查和对抗性检测不是一次性设计步骤，而是系统自身永久运行的组成部分。**

---

## 安全边界（第 65 节）

这是一个传统术数与个人预测实验平台，**不是经科学验证的预知系统**。

系统不得：

- 以术数诊断疾病；
- 预测死亡日期；
- 替代医生；
- 替代律师；
- 替代财务专业人士；
- 鼓励高风险下注；
- 因为面部特征推断敏感人格事实。
